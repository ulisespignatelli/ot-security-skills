# IEC 62443 y el modelo Purdue: lo necesario para esta revisión

IEC 62443 es la familia de normas internacionales de ciberseguridad para sistemas de automatización y control industrial (IACS). Este resumen está en palabras propias; para una evaluación formal hay que usar las normas oficiales.

## Partes más usadas
- **62443-2-1:** programa de seguridad del dueño del activo (políticas, inventario, gestión de cambios).
- **62443-3-2:** evaluación de riesgos y diseño de **zonas y conductos**, con un nivel de seguridad objetivo por zona.
- **62443-3-3:** requisitos técnicos del sistema, organizados en siete requisitos fundamentales y graduados por nivel de seguridad.
- **62443-4-1 / 4-2:** desarrollo seguro y requisitos para componentes, para fabricantes.

## Zonas y conductos
- **Zona:** conjunto de activos con requisitos de seguridad comunes (por ejemplo, la celda de bombeo o el SIS).
- **Conducto:** canal de comunicación entre zonas. Todo el tráfico entre zonas pasa por un conducto definido y controlado (firewall, diodo de datos, gateway), con una lista explícita de lo permitido.
- Cada zona tiene un **nivel de seguridad objetivo (SL-T)**: SL1 protege contra errores y accesos casuales; SL2, contra ataques intencionales con pocos recursos; SL3, contra atacantes con recursos moderados y conocimiento de IACS; SL4, contra atacantes con muchos recursos.

## Requisitos fundamentales (FR)
| FR | Nombre | Qué cubre en esta revisión |
|---|---|---|
| FR1 | Identificación y autenticación | protocolos industriales sin autenticación y accesos remotos sin MFA |
| FR2 | Control de uso | quién puede hacer qué (acceso de proveedores, programación de PLC) |
| FR3 | Integridad del sistema | proteger la lógica y la configuración (SIS, rutas de ransomware) |
| FR4 | Confidencialidad de los datos | protocolos en texto claro |
| FR5 | Flujo de datos restringido | **segmentación: el núcleo de esta revisión** |
| FR6 | Respuesta oportuna a eventos | registro de conexiones denegadas y monitoreo |
| FR7 | Disponibilidad de recursos | inventario, resiliencia, que la seguridad no frene el proceso |

## Modelo Purdue (referencia para asignar niveles)
| Nivel | Qué hay | Ejemplos |
|---|---|---|
| L0 | Proceso físico | sensores, actuadores, variadores |
| L1 | Control | PLC, RTU, IED, controladores DCS, **SIS** (en zona propia) |
| L2 | Supervisión del área | HMI, servidor SCADA, estación de ingeniería, servidor OPC |
| L3 | Operaciones del sitio | historiador, MES, Active Directory de OT, servidor de parches |
| L3.5 | **DMZ industrial** | jump host, réplica del historiador, gateway de acceso remoto, transferencia de archivos |
| L4 | Empresa (IT) | ERP, correo, PCs de oficina |
| L5 | Internet y nube | proveedores, servicios externos |

Principios que se derivan:
1. **Nada cruza de L4 a L3 o niveles inferiores directamente:** todo termina en la DMZ industrial.
2. Los niveles se comunican con el **adyacente**; los saltos se justifican y se acotan.
3. El **SIS** tiene una zona propia con el conducto más restrictivo de la planta.
4. El acceso remoto entra por la DMZ, con MFA, por un jump host y con sesiones registradas.
5. **Lista blanca:** cada conducto permite solo las comunicaciones documentadas y termina en "denegar todo".

El modelo Purdue es una referencia, no una ley: las arquitecturas modernas (nube, IIoT) lo flexibilizan. Lo que no cambia es el principio de zonas, conductos y mínimo privilegio.
